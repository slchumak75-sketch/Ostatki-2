## Инварианты — НЕ ЛОМАТЬ

1. **Go и Python алгоритмы — зеркала.** Меняешь формулу в одном месте → меняй в другом, обновляй
   ALGORITHM.md, тесты и контрольные цифры (здесь и в BUILD.md).
2. **JSON-контракт** (`internal/model` ↔ `app.js` ↔ `dev_server.py`): имена полей camelCase синхронны.
3. **Ноль внешних Go-зависимостей** (иначе появится go.sum — тогда обнови workflow: cache setup-go
   и этот пункт). XLSX — вручную через zip/XML; оформление оригинала при экспорте из Go НЕ сохраняется
   (осознанно, v1); оформление сохраняет только Python-путь.
4. **Столбец «К закупке» — 8-й (H)** и в исходной ведомости, и в генерируемой книге. Парсер определяет его
   как пустой столбец между «Конечный остаток» и «Цена поставщика».
5. Оригинальный xlsx в корне — **не перезаписывать** (результаты → `output/`), он же фикстура CI smoke-теста.
6. Сервер — только `127.0.0.1` (Go). `0.0.0.0` допустим лишь в dev-сервере для превью песочницы.

## Грабли, уже найденные в данных (не наступать второй раз)

- «Расход» (F) ≠ сумме месяцев у 828 строк — прогноз только по месяцам.
- Розница пуста ровно при остатке 0 (904/1850 заполнены) — оценка по медианной наценке группы, флаг «оценка».
- Числа — строки (`"8.00"`, `" "`); в двух ячейках розницы — два числа через `\n`, актуально последнее.
- Октябрь 2026 неполный → `partialLast=true` по умолчанию; «запас, мес.» считать от десезонализированного темпа.
- Медианный товар продаётся в 5 из 36 месяцев → сезонность товара обязательно сглаживать к группе (shrinkage K=30).
- Тысячи с пробелом (`1 234,5`) парсятся как последнее число (234,5) — задокументированное ограничение ParseNum.
