# Алгоритм «К закупке» с учётом сезонности

Реализации (обязаны совпадать): Go — `internal/forecast/forecast.go`, Python — `tools/forecast.py`.
Тесты: `internal/forecast/forecast_test.go`.

## Параметры (меняются в GUI)

| Параметр | По умолчанию | Смысл |
|---|---:|---|
| `horizon` | 3 | на сколько **полных** месяцев вперёд закупаем |
| `safetyPercent` | 20 | страховой запас, % от прогноза на горизонт |
| `leadDays` | 14 | срок поставки, дней (спрос за время ожидания поставки) |
| `deadMonths` | 12 | нет продаж N полных месяцев → рекомендация 0 («мёртвый» товар) |
| `partialLast` | true | последний помесячный столбец — неполный текущий месяц |
| `useTrend` | true | затухающий тренд для SKU с продажами ≥ 36 ед. за историю |
| `shrinkageK` | 30 | константа сглаживания сезонности товара к группе (в GUI не выведен) |

## Шаги расчёта для каждого товара

1. **История** — помесячные продажи. Если `partialLast`, последний столбец исключается из истории
   (он неполный); полных месяцев в исходном файле 36 (окт 2023 — сен 2026).

2. **Индексы сезонности** `I[c]`, c = 1..12, среднее = 1:
   - глобальный — по всем товарам; групповой — по товарам группы (если суммарные продажи группы < 100, берётся глобальный);
   - сырой индекс товара: средние продажи в календарном месяце c / средние продажи за месяц вообще;
   - **сглаживание (shrinkage)**: `Iтовара = w·Iсырой + (1−w)·Iгруппы`, `w = продажиТовара / (продажиТовара + K)`, K = 30.
     У товара с 11 продажами за 3 года w ≈ 0,27 — в основном работает сезонность группы;
     у хита с 1000 продаж w ≈ 0,97 — своя сезонность. Индексы нормируются к среднему 1 и ограничиваются [0,15 … 3,0].

3. **Базовый уровень** `B` — десезонализированное среднемесячное потребление за последние 12 полных
   месяцев: `B = mean(продажи[t] / I[месяц(t)])`. Если за эти 12 мес. продаж не было, но были раньше —
   берётся вся история (пригодится при `deadMonths > 12`).

4. **Тренд** (если включён, продаж ≥ 36, истории ≥ 24 мес.): отношение десезонализированных продаж
   последних 12 мес. к предыдущим 12, затухание 50%, итог ограничен [0,75 … 1,40]. `B *= тренд`.

5. **Прогноз по месяцам**: `F[m] = B · I[месяц(m)]`. Период прогноза — `horizon` полных месяцев,
   начиная со следующего за последним полным; **плюс** остаток неполного месяца, если `partialLast`:
   для него `F = max(0, B·I − уже продано в этом месяце)`. Пример при файле-октябре-2026 и horizon=3:
   остаток окт 2026 + ноя 2026 + дек 2026 + янв 2027.

6. **Потребность**: `Need = ΣF + Fсред(полных мес.) · leadDays/30,44 + ΣF · safetyPercent/100`.

7. **Рекомендация**: `Кзакупке = ceil(max(0, Need − Остаток))`. Для дробных товаров (дробные продажи/остаток)
   округление вверх до 0,01. **Защиты:** если продаж за последние `deadMonths` полных месяцев не было
   или товара не продавалось вообще — **0** независимо от остатка.

## Статусы и дополнительные показатели

- `urgent` — рекомендация > 0 и остаток = 0; `order` — рекомендация > 0 при остатке > 0;
  `dead` — нет продаж `deadMonths` мес.; `excess` — остатка хватит > 12 «средних» месяцев
  (`Остаток / B`, именно десезонализированный темп — иначе зимой летний товар ложно «избыточен»);
  `ok` — остальное.
- Маржа = (розница − закупка) / розница; наценка = (розница − закупка) / закупка.
  Если розницы нет (в файле она пуста при остатке 0), розница оценивается как
  `закупка · (1 + медианная наценка группы)` и помечается `retailEstimated`.
- ABC — по валовой прибыли за 12 мес. (`продажи12 · (розницаэфф − закупка)`): A до 80% накопленной прибыли, B до 95%.
- Регулярность спроса по числу месяцев с продажами за историю: ≥18 регулярный, 6–17 нерегулярный, <6 эпизодический.
- Сумма заказа = рекомендация × цена поставщика (0/пустая цена занижает бюджет — есть предупреждение в GUI).

## Ограничения v1 (честно)

- Не учитываются: товар в пути/уже заказанный, кратность упаковки и мин. партия поставщика, сроки годности,
  перемещения между складами Мир↔Кореличи, возвраты. «Расход» из файла не используется (см. ANALYSIS.md, п. 2.1).
- Прогноз точечный, без доверительных интервалов; страховой запас — процентный, а не через σ спроса
  (для разреженных рядов σ шумит сильнее, чем помогает).
- Дубли названий не склеиваются: каждая строка файла = отдельный товар.
