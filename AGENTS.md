# AGENTS.md — Руководство для ИИ-агентов и разработчиков по продолжению проекта `Ostatki-2`

Этот документ содержит исчерпывающий контекст архитектуры, формата Excel-файла 1С, математической модели сезонного прогнозирования, кодовой базы Go и CI/CD-пайплайна, чтобы любой агент мог мгновенно ориентироваться в репозитории и безопасно развивать проект.

---

## 1. Обзор задачи и карта репозитория

Проект решает задачу автоматического расчёта **Столбца 8 (`H` — «К закупкам»)** в отчёте 1С *«Ведомость по остаткам ТМЦ на складах»* на основании помесячной сезонной статистики продаж и представляет собой автономное Windows-приложение на **Go 1.24** с **HTML GUI** (`CGO_ENABLED=0`, **ноль внешних зависимостей** в `go.mod`).

## 2. Точная спецификация исходного Excel-файла (`Ведомость с периодом ОК (1).xlsx`)

При доработке парсера/экспортёра **обязательно учитывайте следующие реальные особенности выгрузки 1С**:

1. **Лист и размеры:**
   - Лист: `Лист_1` (`xl/worksheets/sheet1.xml`), диапазон `A1:AV1857` (`1 857` строк, `48` столбцов).
   - Строка `4`, ячейка `D4`: заголовок отчёта `'Ведомость по остаткам ТМЦ на складах'`.
   - Строка `7`: шапка таблицы (`HeaderRow = 7`).
   - Строки `8..1857`: ровно `1 850` товарных позиций без промежуточных подытогов:
     - Строки `8..792` (`785` позиций): `Склад Кореличи`, группа `2 краски растворители`.
     - Строки `793..1857` (`1 065` позиций): `Склад Мир`, группа `2 замки фурнитура`.
2. **Схема столбцов (строка 7):**
   - `1 (A)`: `Склад` (строка `t="s"`)
   - `2 (B)`: `Группа номенклатуры` (строка `t="s"`)
   - `3 (C)`: `Артикул` (строка `t="s"`, часто `' '`)
   - `4 (D)`: `Номенклатура` (строка `t="s"`)
   - `5 (E)`: `Ед.` (`шт`, `банка`, `бут`, `ведро`, `рул.`, `упак` — все целочисленные)
   - `6 (F)`: `Расход` (в 1С выгружен как строка `'8.00'`, а не число!)
   - `7 (G)`: `Конечный\nостаток` (выгружен как строка `'3.00'`; имеет `style="14"` с красной заливкой `00FF0000` в `842` строках, где остаток ниже мин. остатка карточки 1С, и `style="15"` в остальных `1 008` строках)
   - **`8 (H)`**: **Целевой столбец `К закупкам`** (`H7` имеет `s="25"`, строки `H8..H792` имеют `s="19"`, строки `H793..H1857` имеют `s="26"` с целочисленным форматом `numFmtId="164"` = `0;[Red]\-0`)
   - `9 (I)`: `Цена\nпоследнего \nпоставщика` (строка вида `'2.37'`, BYN)
   - `10 (J)`: `Розничная \nцена` (**ВНИМАНИЕ!** При нулевом остатке в 1С ячейка содержит пробел `' '`. А при наличии нескольких партий на складе содержит **несколько цен через `\n`**, например в ячейках `J1317 = '7.00\n9.72'` и `J1793 = '16.00\n22.14'`! Функция `xlsx.ParseFlexibleFloat` специально берёт последнее актуальное числовое значение партии.)
   - `11 (K)`: `Последний\nпоставщик` (`34` уникальных поставщика)
   - `12 (L) .. 48 (AV)`: `37` помесячных столбцов продаж с `'Октябрь 2023 г.'` по `'Октябрь 2026 г.'` (числовые ячейки `<c r="..." s="17"><v>...</v></c>`).
3. **Метаданные и графика 1С (почему критически важен Lossless Writer):**
   - В `docProps/core.xml` записана точная дата формирования выгрузки: `2026-10-19T20:43:37Z` (`19 октября 2026 г.`). Это означает, что последний столбец `AV` (`Октябрь 2026 г.`) содержит продажи только за **19 из 31 дня** месяца (`completeness = 19/31 ≈ 0.6129`)!
   - В `xl/styles.xml` используется нестандартная палитра 1С `<indexedColors>` (`indexed="24"` = `#FFFFC0`, `indexed="10"` = `#FF0000`).
   - В `xl/drawings/drawing1.xml` лежат кнопки управления 1С (`Обновить`, `Настройка`).
   - Обычные библиотеки пересохранения книг часто ломают `indexedColors` или удаляют `drawing1.xml`. Наш `xlsx.WriteOrderColumnLossless` модифицирует **исключительно** `xl/sharedStrings.xml` и теги `<c r="H...">` внутри `xl/worksheets/sheet1.xml` за `O(N)` (~5 мс на 1 850 строк), копируя остальные файлы ZIP-архива **побайтово**.

## 3. Математическая модель расчёта столбца 8 (`internal/forecast/engine.go`)

1. **Нормализация неполного последнего месяца:**
   Если `NormalizePartialLast == true` и год/месяц `CreatedDate` совпадают с последним периодом $T-1$, весовой коэффициент полноты последнего месяца равен $w_{T-1} = \text{clamp}(\text{day} / \text{daysInMonth}, 0.25, 1.0)$, для остальных месяцев $w_t = 1.0$.
2. **Групповые индексы сезонности $I_{g, m}$ ($m \in 1..12$):**
   Вычисляются по суммарным продажам группы $g$ с экспоненциальным весом свежих лет $\gamma_t = \text{decay}^{(T-1-t)/12}$ и нормируются так, что $\frac{1}{12}\sum_{m=1}^{12} I_{g, m} = 1.0$.
   - Фактические индексы на данных репозитория:
     - `2 краски растворители`: Янв `0.25`, Фев `0.37`, Мар `1.01`, Апр `1.36`, Май `1.39`, Июн `1.62`, Июл `1.66`, Авг `1.61`, Сен `1.17`, Окт `0.61`, Ноя `0.47`, Дек `0.49`.
     - `2 замки фурнитура`: Янв `0.47`, Фев `0.48`, Мар `1.00`, Апр `0.90`, Май `1.40`, Июн `1.30`, Июл `1.48`, Авг `1.30`, Сен `0.94`, Окт `0.99`, Ноя `0.99`, Дек `0.76`.
3. **Активное окно и базовый десезонализированный темп SKU $B_i$:**
   Начало активной истории товара `activeStart` определяется первым ненулевым месяцем продаж (с защитой `activeStart <= T - 3`), чтобы новинки не занижались нулями до ввода в матрицу:
   $$B_i = \frac{\sum_{t=\text{activeStart}}^{T-1} \lambda_t \, S_{i, t}}{\sum_{t=\text{activeStart}}^{T-1} \lambda_t \, w_t \, I_{g(i), \text{month}(t)}}$$
4. **Байесовское объединение (Empirical Bayes Shrinkage):**
   $$\hat{D}_{i, m} = \theta_i \, \hat{D}^{\text{direct}}_{i, m} + (1 - \theta_i) \, (B_i \cdot I_{g(i), m}), \qquad \theta_i = \frac{\sum S_i}{\sum S_i + K} \;\;(K = 12)$$
5. **Расчёт целевого запаса и столбца 8:**
   $$\text{Demand}_i = \sum_{d=0}^{\text{HorizonDays} + \text{LeadTimeDays} - 1} \frac{\hat{D}_{i, \text{month}(D_{\text{start}} + d)}}{\text{daysInMonth}(D_{\text{start}} + d)}$$
   $$\text{Target}_i = \text{Demand}_i \cdot \left(1 + \frac{\text{SafetyStockPct}}{100}\right), \qquad \text{OrderQty}_i = \text{round}\big(\max(0, \text{Target}_i - \text{ClosingStock}_i)\big)$$

## 4. REST API контракт (`internal/server/server.go`)

Все запросы фронтенда используют **строго относительные пути** (совместимо и с `http://127.0.0.1:<port>` на Windows, и с reverse-proxy превью):

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/health` | Проверка готовности HTTP-сервера |
| `GET` | `/api/state` | Текущий `CalculationReport`, флаги `canSaveInPlace`, `desktopMode` |
| `POST` | `/api/params` | Обновление `ForecastParams` и мгновенный пересчёт всех 1 850 позиций |
| `POST` | `/api/override` | Установка/сброс ручной правки ячейки столбца 8 (`{excelRow, value, clear, clearAll}`) |
| `POST` | `/api/upload` | Загрузка нового `.xlsx` (`multipart/form-data`, поле `file`) |
| `POST` | `/api/save-inplace` | Lossless-сохранение столбца 8 прямо в открытый на диске файл Excel |
| `GET` | `/api/export/xlsx` | Скачивание заполненной ведомости Excel со 100% оригинальным стилем 1С |
| `GET` | `/api/export/orders` | Скачивание 3-листового `.xlsx` заявок поставщикам (`?warehouse=...&supplier=...`) |
| `POST` | `/api/heartbeat` | Heartbeat открытого окна GUI (каждые 3 сек.) |
| `POST` | `/api/shutdown` | Сигнал мгновенного закрытия при выходе из десктопного окна Windows |

## 5. Быстрые команды проверки для следующего агента

```bash
# 1. Проверить компиляцию и прогнать все тесты с детектором гонок
go vet ./... && go test -v -race ./...

# 2. Обновить столбец 8 в файле ведомости и пересоздать сводные заявки поставщикам
go run ./cmd/ostatki -headless \
  -input "Ведомость с периодом ОК (1).xlsx" \
  -inplace \
  -orders-output "Заявки поставщикам (авторасчёт).xlsx"

# 3. Проверить кросс-компиляцию Windows GUI .exe
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 \
  go build -trimpath -ldflags="-s -w -H=windowsgui" -o OstatkiZakupki.exe ./cmd/ostatki

# 4. Запустить веб-интерфейс в серверном режиме
go run ./cmd/ostatki -server -addr 0.0.0.0:8080
```

## 6. Рекомендуемые направления дальнейшего развития (Roadmap)

1. **Кратность упаковки (`MinOrderPack` / `BoxQty`):** добавить справочник минимальных транспортных упаковок по поставщикам/группам (например, саморезы/шплинты кратно 50/100 шт.).
2. **График поставок поставщиков по дням недели:** индивидуальный `LeadTimeDays` и минимальная сумма бесплатной доставки (`MinOrderAmount BYN`) для каждого из 34 поставщиков с автодобором ходовых позиций класса `A` до минималки поставщика.
3. **Учёт товаров в пути и межскладских перемещений (`Склад Кореличи` ↔ `Склад Мир`):** если на одном складе избыток (`DaysOfSupply > 180`), а на другом дефицит (`OrderQty > 0`), предлагать внутреннее перемещение вместо внешней закупки!
4. **Иконка и ресурсы `.syso` для Windows `.exe`:** встроить `.ico` и `versioninfo` манифест Windows через `goversioninfo` или генератор ресурсной секции PE.
