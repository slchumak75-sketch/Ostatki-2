# Руководство по архитектуре проекта для ИИ-агентов и разработчиков (`AGENTS.md`)

Данный документ описывает устройство двух параллельно поддерживаемых сборок проекта **«Остатки 2»** (`slchumak75-sketch/Ostatki-2`):
1. **Сборка «Вариант 1»** — полностью замороженная и сохранённая базовая версия приложения в директории `variants/variant1/` + эталонный выходной файл `Ведомость с периодом ОК (Вариант 1).xlsx`.
2. **Сборка «Вариант 2»** — основная модернизированная PRO SCM версия в корневых пакетах `cmd/ostatki/` и `internal/` + актуальная заполненная ведомость `Ведомость с периодом ОК (1).xlsx` и 5-листовый отчёт `Заявки поставщикам (авторасчёт).xlsx`.

> **Строгое правило сопровождения:** Никогда не удаляйте и не перезаписывайте код внутри `variants/variant1/` или файл `Ведомость с периодом ОК (Вариант 1).xlsx`, если пользователь явно не попросил изменить именно «Вариант 1». Все дальнейшие улучшения ведите в «Варианте 2» (`cmd/ostatki/`, `internal/`) либо создавайте `variants/variant3/`, сохраняя предыдущие сборки рабочими и компилируемыми.

## 2. Ключевые инварианты формата Excel 1С (`internal/xlsx/`)

1. **Хирургическое обновление ZIP-контейнера (`WriteOrderQuantities`):**
   Запрещено пересохранять исходный `.xlsx` целиком сторонними библиотеками. Модифицируется **только** `xl/worksheets/sheet1.xml`, в котором переписываются строковый узел `H7` и числовые узлы `H8..H<N>`. Все 74 стиля 1С, ширина колонок, группировки и условное форматирование сохраняются побайтово.
2. **Анти-самозацикливание CLI:**
   При автопоиске входного `.xlsx` без флага `-input` программа автоматически пропускает служебные файлы (`Заявки поставщикам*` и `*(Вариант 1)*`).

## 3. Архитектура математического ядра «Варианта 2» (`internal/forecast/engine.go`)

1. **Детектирование и подавление разовых оптовых выбросов (`winsorizeItemSales`):**
   Анализирует ненулевые месячные продажи каждого SKU, вычисляет 75-й перцентиль (`P75`) и ограничивает экстремальные одиночные всплески порогом `max(P75 × 3.2, 2-й максимум × 2.2)`. Очищенные ряды используются **и для расчёта сезонных индексов групп**, и для индивидуальной скорости продаж SKU.
2. **Двумерная матрица `ABC × XYZ` (`classifyXYZ`, `MatrixABCXYZ`):**
   - `ABC` — вклад позиции в совокупную выручку / оборот (`A`: 80%, `B`: 15%, `C`: 5%).
   - `XYZ` — стабильность очищенного спроса (`X` стабильный `CV ≤ 0.65`, `Y` сезонно-умеренный `CV ≤ 1.25`, `Z` прерывистый эпизодический).
3. **Аппроксимация Синтетоса–Бойлана (`Croston / SBA`) и адаптивный SLA:**
   Для Z-позиций применяется поправка `1 − α/2` (`×0.85` к интенсивности спроса), а страховой запас умножается на матрицу приоритетов (`AX: ×1.25`, `AY: ×1.15`, …, `CZ: ×0.50`).
4. **Оптимизатор лимита бюджета (`applyBudgetCapOptimizer`):**
   Если `BudgetCap > 0`, каждая заказываемая единица каждого SKU получает рейтинг `PriorityScore` (дефицит на полке + класс `ABC` + маржинальность + сезонный индекс). Жадный упаковщик с добором мелких недорогих хитов укладывает итоговый заказ строго в заданный бюджет.
5. **Онлайн-сравнение с «Вариантом 1» (`Variant1OrderQty`, `DeltaFromV1`):**
   При каждом пересчёте движок параллельно вычисляет базовую формулу «Варианта 1», позволяя мгновенно видеть экономию и построчные причины корректировок в GUI и на 5-м листе Excel.

## 4. Команды проверки и сборки

```bash
# Полная проверка статического анализатора и всех тестов обеих сборок
go vet ./... && go test -v -race ./...

# Пакетный пересчёт ведомости и 5-листового отчёта «Варианта 2»
go run ./cmd/ostatki -headless \
  -input "Ведомость с периодом ОК (1).xlsx" \
  -inplace \
  -orders-output "Заявки поставщикам (авторасчёт).xlsx"

# Запуск веб-сервера для предпросмотра (строго на 0.0.0.0)
go run ./cmd/ostatki -server -listen 0.0.0.0:8080 -input "Ведомость с периодом ОК (1).xlsx"
```
